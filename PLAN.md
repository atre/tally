**Found by a second review pass, fixed before commit:**
- `--session` bypassed the file-mtime prefilter but `parseTranscript` still got the original (recent, default) `--since`, so a session older than the window scanned as `files:1, turns:0` — silently empty instead of silently missing. Root cause was CLI-layer, not scan.ts: there's no way to tell "explicit `--since`" from "defaulted `--since`" once both resolve to the same timestamp. Added `Args.sinceExplicit` + `effectiveSince(args)` (cli.ts, exported/tested) — `--session` alone implies `since=0`; an explicit `--since` still narrows it. `tally diff` picked up the same fix and, while there, the missing `!s.files` guard other subcommands already had.
- `CURL_SH_RE` required the shell name immediately after the pipe (`\| ?(ba|z)?sh\b`) — `curl … | sudo bash` (or `env bash`, `exec bash`) walked straight past it. Added the common wrapper words to the pattern.
- `SED_I_RE`/`SED_I_REPLACE_RE` matched `sed -i` anywhere in the string, including inside an unrelated quoted argument (`echo "... sed -i ..."` got silently rewritten). Anchored to a command boundary (`^` or after `;`/`&`/`|`) — a real fix would need actual shell tokenizing, out of scope for a regex guard, but this closes the obvious case. Cost: the boundary is now captured and must be re-emitted in the replacement (`"$1sed -i ''"`, not `"sed -i ''"`) or the boundary character itself gets eaten.
- `pre-read`'s skip condition was `limit || offset` — an `offset` with no `limit` reads unbounded to EOF, which is the exact case this guard exists to catch, not a reason to skip it. Now only `limit` skips.
- `renderJson` never received the fetched `--poolpool` rows (renderText/renderMd did) — added the param.
- `lastUsage` (ctx-guard) didn't filter `isSidechain`, unlike every other "context" computation in this codebase (scan.ts, analyze.ts) — a trailing subagent record in the transcript tail would make ctx-guard react to the wrong session's size.
- `mergeHooks` assumed `settings.hooks[event]` was always an array; a hand-corrupted settings.json (e.g. `{}` instead of `[]`) threw an uncaught TypeError instead of a clean recovery.

**Found by a third review pass (covering Phase 2's tail + all of Phase 2.5 above), fixed before commit:**
- Two more guard bypasses, same class as the second pass's: `CURL_SH_RE` still couldn't cross a *second* pipe stage (`curl … | tee x | bash` walked past `[^|]*\|`), split into two independent checks (`curl|wget` present anywhere + a shell invocation at any pipe stage) instead of one adjacency pattern. `SED_I_RE`'s command-boundary anchor (`^`/`;`/`&`/`|`) didn't include a newline, so `sed -i` on a later line of a multi-line Bash command — routine for this tool — was never caught; added `\n` to the boundary class.
- `tally hooks --suggest` used raw `args.since` and dropped `args.session` entirely, reintroducing the exact bug `effectiveSince`/`--session` forwarding fixed everywhere else. `tally tools` had the same missing `session` forward. Both fixed.
- `runPostBashMark`'s "used from inside its own repo" check was an exact `cwd === repo` match, so a subdirectory of the tool's own repo (`<repo>/src`) wasn't recognized as "own repo" and got wrongly marked as external usage. `toolsReport`'s equivalent check was worse: `project` is a lossy last-two-path-segments label that can't reconstruct repo containment below one directory of depth. - `--json`/`--md`/`--brief`/`--cost`/`--poolpool` had no effect on `snap`/`diff`/`tools`/`hook(s)`/`trace` and failed silently. Wired the two that were cheap and worth actually supporting (`snap --cost`, `diff --json`); everything else now throws a clear "not supported by tally `<cmd>`" instead of silently doing nothing.

## Phase 4 — tracer (live view; same repo, `tally trace`)
Tally is the batch view of token spend; tracer is the live one. Same parser,
same digest discipline, no server/DB/UI — that's the niche (Langfuse/LangSmith/
Braintrust/Phoenix/AgentOps all want a backend + web UI; Claude Code's native
OTel export is raw metrics, not "why did this session cost €40").
- [x] `tally trace [--session <id>|--follow]` — tail the active transcript; one line per turn: ctx size, Δ, tool, result tokens, bucket hit (cost est waits on the pricing.json item)
- [x] spans: tool_use → tool_result paired (duration via `completedTs`, size, error tag, ×3 retry warn, `[side]` sidechain tag; no tree nesting yet)
- [x] live thresholds: warn when ctx crosses `--ctx-limit` and 2×, when a loop repeats (same tool+args ≥3); single result > N shows as [huge]/[big] tag — feeds Phase 2 hooks
